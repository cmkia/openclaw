# Magnific illustration workflow

Magnific is an authenticated MCP connected to OpenClaw. OmniRoute chooses the reasoning model; it does not generate the image or hold the image-generation job. Discover the currently enabled Magnific tools and read their schemas instead of assuming prefixes or hardcoding a model ID.

1. Identify which slides need a conceptual illustration. Prefer one purposeful asset reused across related slides over a decorative image for every slide.
2. Consult the enabled model catalog and cost simulation (`simulate_cost` when available). Select an available image model that fits the requested quality and any configured task budget. A request to create a presentation with Magnific illustrations authorizes the ordinary necessary generations using existing credits: choose a modest image count, reuse suitable assets, and proceed without a separate approval for each image. Ask only when a purchase is needed, an explicit limit would be exceeded, or the requested scope leaves a consequential cost unresolved. Never silently exceed an authorized limit.
3. Use the generation tool (`images_generate` when available), record the returned creation identifier, and await it with the service's wait/status tool (`creations_wait` / `creations_get` when available). A returned job ID is not a finished image. Do not submit duplicates while a job is pending; reconcile status before retrying an uncertain request.
4. `creations_wait` / `creations_get` can return a temporary signed HTTPS image URL. Download that completed asset with **`python3`**, using `{baseDir}/scripts/download_image.py --output presentations/<task-slug>/images/<asset-name>.jpg` (or `.png` matching the returned format). Pass the URL only through the process's stdin using the execution tool's structured input or a private temporary source file. Never concatenate it into shell code, expose its query in chat/logs, or write it into provenance. Use `--workspace` only when the execution cwd and `OPENCLAW_WORKSPACE_DIR` do not identify the tenant workspace. The helper returns the local relative path, byte count, SHA-256, and format; it rejects nonpublic destinations, unsupported images, and existing output files.
5. Download first, then inspect the local image with the available `view_image` or image-capable `read` tool. **Do not use a browser, computer control, or `creations_show` to obtain the file.** These are unnecessary for an HTTPS asset returned by MCP. Use `python3`, not an assumed `python` binary. On a download failure, reconcile the existing creation and URL or fix the path/extension; do not submit another paid generation or loop through unavailable GUI tools. Check conceptual accuracy, unwanted text, misleading geometry, crop, and contrast. Generate an alternative only for an actual failed illustration requirement. Layout revisions reuse approved image files.
6. In the manifest's image provenance, set `kind: "generated"`, the actual `model` and `creationId`, and `description` containing the prompt and conceptual status. Preserve verified bibliographic source references, not a temporary signed download URL. Add the same conceptual qualification in the relevant notes. An image made by AI must not be presented as microscopy, a patient scan, a measured dose map, or experimental evidence.

## Prompt pattern

“Conceptual biomedical illustration for a radiotherapy teaching presentation: [one verified mechanism]. Dark near-black environment, restrained blue/cyan/violet palette, [subject] positioned on the right with quiet negative space on the left. Scientifically plausible proportions, clear focal hierarchy. No text, labels, numbers, axes, charts, watermark, or clinical imaging appearance. Educational illustration; not patient data.”

Adapt this to the actual source. Describing the intended visual mechanism is more useful than generic requests for “medical realism.” Put labels, numerical values, and explanatory arrows in editable slide content whenever their placement carries meaning.

For an original textbook figure, record `kind: "source"`, the title and verified locator; for an appropriately licensed asset, record `kind: "licensed"` and its source/license. Possession of a public link does not establish permission to publish an image elsewhere.
